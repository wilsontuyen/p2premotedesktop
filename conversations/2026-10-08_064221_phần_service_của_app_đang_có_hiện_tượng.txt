## Root Cause & Fix

**Nguyên nhân:** Trong `get_active_session_id()`, khi service phát hiện một session ở trạng thái `WTSDisconnected` (có user token), nó tự động gọi:

```bash

```

Lệnh này chuyển session RDP đó về console, làm Ms RDP bị **đá văng** ngay lập tức. Điều này xảy ra liên tục mỗi vòng poll (mỗi ~1 giây).

**Fix:** Thêm hàm helper `_is_rdp_session()` kiểm tra `WTSClientName` của session:
- Session **RDP từ xa**: có `WTSClientName` (tên máy client) → **bỏ qua `tscon`**, return session đó để service vẫn spawn agent trong session RDP
- Session **console/local**: `WTSClientName` rỗng → vẫn gọi `tscon /dest:console` như bình thường

Hàm này được guard ở cả **2 nơi** trong `get_active_session_id()`:
- Block chính (dòng 300+): session Disconnected có user token
- Block fallback (dòng 331+): session Disconnected còn lại
