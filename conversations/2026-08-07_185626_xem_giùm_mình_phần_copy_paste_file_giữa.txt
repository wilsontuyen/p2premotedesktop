## Root Cause

The problem is in the **delayed rendering mechanism** (`WM_RENDERFORMAT`). The flow currently works like this:

1. **Remote side copies files** → sends `files_copied_meta` to local
2. **Local receives `files_copied_meta`** → calls `setup_delayed_rendering()` which sets up `CF_HDROP` with `NULL` handle (delayed rendering)
3. **Windows sends `WM_RENDERFORMAT`** when ANY application tries to read the clipboard data — including when the user just **right-clicks** to open the context menu

The issue is that Windows Explorer sends `WM_RENDERFORMAT` just to **preview/query** clipboard data when building the context menu (to decide whether to enable/disable the Paste option). The current `render_format()` method **immediately starts downloading files** on any `WM_RENDERFORMAT`, instead of only when the user actually clicks "Paste".

The `check_is_menu_query` function exists but is **never called** in `render_format()` — it has dead code after `return False` at line 347 and is unreachable.
